# JLPT総合学習システム制作引継ぎ仕様書
（① 読解・聴解演習【プランB】メガ盛り拡充 ＋ ② 本番模擬試験 各レベル10回分）

本ドキュメントは、新しいチャットで「読解・聴解演習の大量拡充（メガ盛り）」および「各レベル10回分の本番模擬試験」の制作・監査をミスなく継続するための完全引き継ぎ仕様書です。

---

## 1. 2大タスクの明確な区分（ユーザー確認済み）

ユーザーが求めているのは、以下の**独立した2つの制作タスク**です。混同を絶対に避けてください。

### 【タスクA】読解・聴解 演習道場（各レベルの reading / listening ページ）の【プランB】メガ盛り拡充
- **対象画面**: 各レベルの `jlpt_n{level}_reading.html` および `jlpt_n{level}_listening.html`
- **背景**: 以前に少なめ（お試し・初期版）で作成したリスニング・リーディングの演習問題プールを、本格的に超大規模拡充する。
- **目標規模**:
  - **読解（Reading）**: 全レベル（N1〜N5）合計 **約 500〜800問**
  - **聴解（Listening）**: 全レベル（N1〜N5）合計 **約 800〜1,500問**（全問TTS事前平仮名化＋実音声検証）
  - **総演習問題数**: **約 1,300〜2,300問**

### 【タスクB】本番そっくり模擬試験（Mock Exam）各レベル10回分
- **対象画面**: 各レベルの `jlpt_n{level}_mock.html`
- **内容**: 公式ガイドブック（`guidebook_s_j.pdf`）に準拠した、本番と同じ試験時間・大問構成・問題数の**フル模擬試験を各レベル10回分（計50回分）**作成。
- **機能**:
  - 文字・語彙、文法、読解、聴解の全セクション
  - 項目応答理論（IRT）に基づく尺度得点シミュレーション
  - 合否判定（総合得点＋基準点足切り）
  - 合格・不合格リザルトモーダル（プードルイラスト右側配置、ローズグラデーション配色、英語併記ボタン）
  - 間違えた問題だけ復習モード、全問解説モード

## 2. これまでユーザーに指摘された「厳格チェックルール」（再発防止の鉄則）

制作後には、以下の全項目をスクリプトおよび目視・聴覚で必ず点検し、ミスがあれば自動訂正すること。

| # | 指摘項目 | 原因 | 確定した仕様・解決コード |
| :--- | :--- | :--- | :--- |
| 1 | **音声TTSの不自然な読み**<br>（例: 「持って来なければ」が「きなければ」になった。「問題一」が「もんだいはじめ」になった） | Google Cloud TTSがカ変動詞の活用や漢字数字を文脈なしで誤読した。また生成後の実音声検査を怠った。 | **`text_for_tts()` による100%事前平仮名化**：<br>・`持って来なければ` ➔ `持ってこなければ`<br>・`来なければ` ➔ `こなければ`<br>・`来なかった` ➔ `こなかった`<br>・`来ない` ➔ `こない`<br>・`遊びに来ました` ➔ `遊びにきました`<br>・`問題一` ➔ `問題１`（「もんだいいち」に強制）<br>・`一番` ➔ `１番`（「いちばん」に統一）<br>・**音声生成後にSpeech-to-Textや`read_file`で文字起こしし、発音を全問耳と目で検証する義務** |
| 2 | **下線（アンダーライン）の二重線** | 全角アンダーバー文字 `＿＿` と HTMLタグ `<u>` が重なり、線が2本になっていた。 | `<u>＿＿</u>` を完全廃止し、`<span class='jlpt-underline-blank'></span>` を使用。 |
| 3 | **下線の太さと色** | 下線が太すぎて色が不揃いだった。 | **極細1.5px**、色は指定ティール（`#14778B`）に完全統一。<br>`border-bottom: 1.5px solid #14778B;` |
| 4 | **模擬試験エリアでのルビ非表示** | ふりがなスイッチON時に漢字読み問題等の漢字の上にルビが表示され、答えがネタバレしていた。 | 本番試験同様、**問題文・選択肢のルビを完全非表示**に固定。<br>大問指示文（`＿＿の ことばは どう かきますか` 等）のみルビを許可。 |
| 5 | **文法問題の「どれも正解になりうる曖昧さ」** | 「ここで写真を（　）。」など、前提文脈がないため選択肢のどれでも文法的に成立してしまっていた。 | 「美術館の中ですから、ここで写真を（　）。」のように**前提文脈・条件を必ず付与**し、客観的・文法的に正解が1つだけに定まるように徹底。 |
| 6 | **文の組み立て問題（★問題）の★の位置** | ★の位置がすべて3番目に固定されていた。 | 公式本番試験同様、**1番目・2番目・3番目・4番目の各位置に適切に分散**させる。 |
| 7 | **採点方式（IRT尺度得点シミュレーション）** | 単なる正答数素点ではなく、JLPT公式のIRTモデルを模す必要があった。 | IRTシミュレーションによる尺度得点計算を実装。<br>結果画面に以下の注記を明記：<br>`※JLPT本番では単なる素点計算ではなく、項目応答理論（IRT）に基づく「尺度得点」が用いられます。本システムでもこの公式モデルをシミュレーションして算出しています。` |
| 8 | **合格・不合格モーダルのデザイン** | 赤背景が強すぎた、イラストの配置が文字の左だった。 | ・不合格ヘッダー背景＆復習ボタン: `linear-gradient(135deg, #B8596E, #CE5A73)`（ソフトローズ）<br>・ボタン英語併記: `🔴 間違えた問題だけ復習する (Review Incorrect Only)` / `全問解説 (All Explanations)`<br>・**プードルイラストはタイトルの右側に配置**（合格: バンザイ `poodle_pass.png`、不合格: 困り顔 `poodle_fail.png`） |
| 9 | **練習問題・例文との重複禁止** | 既存の文法道場やフラッシュカードの例文と同じ問題文が出題されるリスク。 | 既存データとの**重複ゼロ（Zero Overlap）**を徹底。すべて本番用の完全新規オリジナル問題とする。 |
