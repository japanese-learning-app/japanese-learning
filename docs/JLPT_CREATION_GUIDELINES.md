## 5. 音声読み上げ（TTS）の絶対ルール（ルビ2重読み上げ防止）

ユーザーから最も厳しく指摘された重大バグです。**すべての音声再生関数で例外なく以下の前処理を実装すること**。

### 🚨 2重読み上げの原因と完全防止コード
HTMLタグ `<ruby>大雨<rt>おおあめ</rt></ruby>` を単に `replace(/<[^>]+>/g, '')` すると、`大雨おおあめ` と漢字とルビが連続結合し、音声エンジンが「大雨」と「おおあめ」を2回連続で発音してしまう。

```javascript
// ✅ 正しい音声テキスト抽出処理（必ず <rt>...</rt> を先に消す）
function extractSpeechText(htmlText) {
  if (!htmlText) return '';
  return String(htmlText)
    .replace(/<rt>[\s\S]*?<\/rt>/gi, '') // 1. ふりがな部分を完全除去
    .replace(/<[^>]+>/g, '')             // 2. 残りのHTMLタグを除去
    .replace(/（\s*）|\(　*\)|（　*）/g, '、') // 3. 空欄は自然な一呼吸（読点）に置換
    .replace(/（する）|\(する\)/g, '')   // 4. 不要な品詞カッコを除去
    .replace(/[【】]/g, '')               // 5. 強調カッコを除去
    .replace(/\s+/g, ' ')                // 6. 連続空白を1つに整理
    .trim();
}
```

### 🔊 音声再生エンジンのハイブリッド設計
- 単語単体の発音は、多音字の誤読を防ぐため **`reading`（ひらがな）を最優先** で渡す。
- 例文・問題文は、上記の `extractSpeechText()` を通した**自然な漢字かな交じり文**を渡す（文脈アクセントが最も自然になるため）。
- **Google TTS API（高音質）を優先** し、通信制限やブロック時は **Web Speech API（SpeechSynthesisUtterance）に自動フォールバック** させる。

## 6. 問題文・例文の品質 & OCR文字化けの絶対根絶ルール

1. **OCR欠落・誤認識の完全排除**
   - 「食できたのは」➔ 「合格できたのは」
   - 「太学に食べ」➔ 「大学に合格」
   - 「新しい企画のウイルスについて…」のような機械的テンプレート文は禁止。**100%自然な実生活・JLPT本試験に即した日本語文**にする。
2. **問題文への選択肢混入（ベタ貼り）の禁止**
   - 例: 「家族の協力をめぐって私の成功はなかった」のように、空欄 `（　　　）` が消えて正解が問題文に最初からネタバレ混入している不具合を絶対に起こさないこと。
3. **空欄の表記統一**
   - 空欄の中に「？」や「【空欄】」「【 空欄 】」などの不要な文字を入れない。
   - 必ずすっきりした **`（　　　）`**（全角スペース3つ程度）で統一する。
4. **不要な「（する）」の根絶**
   - 問題文「今月のしょうひ（する）」等の不自然な（する）は完全に消す。
   - 語彙カードの `reading` 欄に「あいず（する）」と入れない（表示時に `（あいず（する））` と二重カッコになるため）。`reading` は純粋な平仮名「あいず」にする。

### 🎲 全問初期シャッフル＆「10問/30問/50問」満遍ない分散選出の共通コード
```javascript
// 1. Fisher-Yates シャッフルヘルパー
function shuffleArray(array) {
  if (!array || !array.length) return [];
  const arr = [...array];
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}

// 2. 満遍なく・バランスよく問題を選出してシャッフルする共通ヘルパー
function buildBalancedIndices(data, limit, filterVal = 'all') {
  if (filterVal !== 'all') {
    const gid = parseInt(filterVal, 10);
    const matched = [];
    for (let i = 0; i < data.length; i++) {
      if (data[i].grammar_id === gid) matched.push(i);
    }
    const shuffled = shuffleArray(matched);
    return (limit > 0 && shuffled.length > limit) ? shuffled.slice(0, limit) : shuffled;
  }

  // 全問モード: 最初から全問完全シャッフル
  if (!limit || limit <= 0 || limit >= data.length) {
    return shuffleArray(data.map((_, i) => i));
  }

  // 厳選問題（10問、30問、50問等）: 文法項目（grammar_id）ごとに満遍なく分散選出
  const grammarGroups = new Map();
  data.forEach((q, idx) => {
    const gid = q.grammar_id;
    if (!grammarGroups.has(gid)) grammarGroups.set(gid, []);
    grammarGroups.get(gid).push(idx);
  });

  const shuffledGroups = new Map();
  grammarGroups.forEach((indices, gid) => {
    shuffledGroups.set(gid, shuffleArray(indices));
  });

  const grammarIds = shuffleArray(Array.from(shuffledGroups.keys()));
  const pickedIndices = [];
  while (pickedIndices.length < limit && grammarIds.length > 0) {
    const currentRound = shuffleArray([...grammarIds]);
    let addedInRound = 0;
    for (const gid of currentRound) {
      if (pickedIndices.length >= limit) break;
      const qList = shuffledGroups.get(gid);
      if (qList && qList.length > 0) {
        pickedIndices.push(qList.pop());
        addedInRound++;
      }
    }
    if (addedInRound === 0) break;
  }
  return shuffleArray(pickedIndices);
}
```

## 17. 【最優先・ゼロトレランス】音声合成（TTS）の不自然な発音・カ変活用・数字誤読の完全根絶基準（「こなければ」「もんだいいち」必須化）

ユーザーから最も厳しく叱責・指摘された重大事項です。「確認は一番得意なはずなのに、なぜ間違えるのか」「全問チェックする時間がないからこそ任せているのに、信頼を損ねてしまった」という反省を胸に刻み、**いかなる例外もなく100%徹底**します。

### 🚨 原因：AI音声合成エンジン（Google Cloud TTS Neural2）の構造的欠陥
- Google TTSは、文脈なしの漢字「来る」の活用（カ変未然形：**こ**ない、**こ**なければ）の文脈判定が非常に苦手であり、`来なければ` を渡すと規則動詞のように **「きなければ」** と自動誤読する。
- 見出しの「問題一」を「もんだい**はじめ**」と誤読する。
- 設問番号の「一番」を「ひとばん」と誤読するリスクがある。

### 🛡️ 恒久対策：TTS前処理フィルター（`text_for_tts`）の絶対適用
すべての音声合成スクリプトにおいて、以下の正規化処理を**100%例外なく事前に実行**してから音声合成APIへ渡すこと。

```python
def text_for_tts(t):
    if not t:
        return ""
    # 1. ルビタグのふりがな（rt）を本文として抽出（漢字ではなく確定読みを渡す）
    # <ruby>来<rt>こ</rt></ruby>なければ -> こなければ
    t = re.sub(r'<ruby>[^<]*?<rt>(.*?)</rt></ruby>', r'\1', t)
    t = re.sub(r'<.*?>', '', t)
    
    # 2. 見出し・セクション番号（「もんだいはじめ」を完全排除し「もんだいいち」に強制）
    t = t.replace('問題一', '問題１').replace('問題二', '問題２').replace('問題三', '問題３').replace('問題四', '問題４')
    
    # 3. 設問番号（「いちばん」「にばん」に完全統一）
    t = re.sub(r'一番(?=[。、\s]|$)', '１番', t)
    t = re.sub(r'二番(?=[。、\s]|$)', '２番', t)
    t = re.sub(r'三番(?=[。、\s]|$)', '３番', t)
    t = re.sub(r'四番(?=[。、\s]|$)', '４番', t)
    t = re.sub(r'五番(?=[。、\s]|$)', '５番', t)
    t = re.sub(r'六番(?=[。、\s]|$)', '６番', t)
    t = re.sub(r'七番(?=[。、\s]|$)', '７番', t)
    
    # 4. カ変動詞「来る」の活用（未然形・連用形・補助動詞）の完全平仮名化
    t = t.replace('持って来なければ', '持ってこなければ')
    t = t.replace('来なければ', 'こなければ')
    t = t.replace('来ない', 'こない')
    t = t.replace('来なかった', 'こなかった')
    t = t.replace('遊びに来ました', '遊びにきました')
    t = t.replace('持って来て', '持ってきて')
    t = t.replace('持って来ます', '持ってきます')
    
    # 5. その他TTS誤読頻出単語
    t = t.replace('一日中', 'いちにちじゅう')
    t = t.replace('何時', 'なんじ')
    t = t.replace('何曜', 'なんよう')
    t = t.replace('何本', 'なんぼん')
    t = t.replace('何人', 'なんにん')
    return t
```

### 🔍 音声生成後の全自動・手動ダブルチェック義務
- 音声ファイルを生成しただけで「完了」としてはならない。
- 必ず生成後のMP3ファイルを音声認識（Speech-to-Textや`read_file`）で文字起こしし、「こなければ」「もんだいいち」「いちにちじゅう」等、誤読が1件も存在しないことを機械的・聴覚的に全件検証してからコミットすること。

### 【タスクA】読解・聴解 演習道場（reading / listening ページ）の【プランB】メガ盛り拡充
- **対象画面**: 各レベルの `jlpt_n{level}_reading.html` および `jlpt_n{level}_listening.html`
- **目的**: 以前に少なめ（お試し・初期版）で作成したリスニング・リーディングの演習問題プールを、本格的に超大規模拡充する。
- **目標規模**:
  - **読解（Reading）**: 全レベル（N1〜N5）合計 **約 500〜800問**
  - **聴解（Listening）**: 全レベル（N1〜N5）合計 **約 800〜1,500問**（全問TTS事前平仮名化＋実音声検証）
  - **総演習問題数**: **約 1,300〜2,300問**

### 【タスクB】本番そっくり模擬試験（Mock Exam）各レベル10回分
- **対象画面**: 各レベルの `jlpt_n{level}_mock.html`（`jlpt_n5_mock.html` 等）
- **目的**: 公式ガイドブック（`guidebook_s_j.pdf`）に忠実に準拠した、本番と同じ試験時間・大問構成・問題数の**フル模擬試験を各レベル10回分（計50回分）**作成する。
- **機能**:
  - 文字・語彙、文法、読解、聴解の全セクション
  - 項目応答理論（IRT）に基づく尺度得点シミュレーション
  - 合否判定（総合得点＋各セクション基準点足切り）
  - 合格・不合格リザルトモーダル（プードルイラスト右側配置、ローズグラデーション配色、英語併記ボタン）
  - 間違えた問題だけ復習モード、全問解説モード

### 🛡️ 共通の制作・監査フロー
1. レベル別に問題データおよびUIを構築。
2. 聴解音声は `text_for_tts` 正規化を100%適用して生成し、生成後に音声認識（`read_file` 等）で発音を全件検査。
3. 作成後は「これまでユーザーに指摘された全項目」（不自然な読み、二重下線、ルビ漏れ、正解バランス、曖昧選択肢、★の位置等）をスクリプトと目視で漏れなく監査・自動修正。
4. 完了後は `verify_all_students_integrity.py` で生徒データ・既存機能への影響ゼロを検証した上でコミット。
